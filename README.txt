DLSS5 简约工具（test6）
========================
导入视频/图片 → 实时预览(原图/DLSS/对比) → 调风格/强度/本地色调/本地结构/皮肤结构
→ 实时播放(带声音、可调音量/速度) → 框选屏幕区域实时渲染 → 导出 DLSS 视频/图片。
皮肤结构支持"双通道遮罩混合"：自动识别人物皮肤区域，把皮肤结构增强限制在皮肤内生效。

【运行】
  双击 run.bat，或命令:  python gui.py

【功能】
  显示下拉:  原图 / DLSS / 对比
    - DLSS: 实时生成当前帧的 DLSS5 神经渲染效果(零引导)，拖动帧进度条或播放逐帧实时看。
    - 对比: 左右分界线，可拖动切换 原图 vs DLSS。
  ▶ 播放: 按视频原帧率实时播放 + 同步声音(空格键也可播放/暂停)。
    - 音量拉条(0-2.00，默认1.00): 播放中随时调节，立即生效；设为 0 即静音。
    - 速度选择(0.25/0.5/0.75/1.0，默认1.0): 选低于 1.0 的速度时【不降分辨率】，
      按原生分辨率渲染(给 GPU 更多时间/帧，适合高分辨率源看满清效果)；1.0 时
      自动降到 ≤720p 保证实时。声音经 atempo 同步变速，音画仍不漂移；
      播放中切速度会从当前播放头用新速度继续。
    - 播放时(速度=1.0)自动把处理分辨率降到 ≤720p 以保证实时(拖动/导出仍是全分辨率)；
      GPU 仍跟不上时画面保持最新已处理帧，播放头/声音按原速继续。
    - 有音频时用音频时钟驱动播放头，音画不漂移；无音频/无声卡时回退视频时钟静音播放。
    - 播放中改 风格/强度/本地色调/本地结构/皮肤结构 会实时生效；拖动时间轴或帧号输入会自动暂停并回到全分辨率。
    - 播到结尾自动循环(音画一起回绕)。
  📌 置顶: "导入"按钮旁的置顶开关——激活后本窗口始终显示在最前(再点一次取消)，
    方便一边看其他内容一边盯实时效果。
  导入图片: 支持 png/jpg/jpeg/bmp/tif/webp，单帧渲染，同样有 原图/DLSS/对比 + 参数调节，
    导出为 <原名>_dlss.png(时间轴/播放/CRF 对图片不适用，自动置灰)。
  DLSS 设置(实时生效): 风格(默认/自然/电影/风格3)、强度(0~5)、本地色调(-2~5)、本地结构(-2~5)、
             皮肤结构(-2~5)。改完立刻刷新。数值项默认 1.00，上限 5.00；强度下限 0，
             其余下限 -2.00；滑条拖动步进 0.01，右侧数值框可手动输入(回车或点别处生效，
             超范围自动钳到各自区间)。音量拉条操作同理(其范围仍为 0-2)。
  皮肤双通道(遮罩混合) [默认开]: 实测离线接入下 NGX 的 skin_struct 参数被引擎皮肤遮罩门控、
             完全惰性(0/10 差异 0.000)；而 local_struct 是活的。所以开启后每帧跑两遍 DLSS:
             A 通道按用户设置(基准)，B 通道用"本地结构 + 皮肤滑条增量"驱动神经模型结构增强，
             再用自动识别的皮肤遮罩把增量混合进皮肤区域——等价于让"皮肤结构"只对皮肤生效。
             遮罩 = MediaPipe 分割(身体/脸部皮肤类) + 人脸椭圆 + "肤色判据×纹理门控"融合:
             分割模型对 CG/动漫角色常把躯干皮肤误判成衣服, 融合判据可补全肩/臂/腹/腿;
             人脸检测用 short+full_range 双检测器在 1024 高分辨率通道跑(全身照小脸也能检出),
             融合判据同样在高分辨率计算(小图下纹理门控失效); 模型 blaze_face_full_range
             可选, 缺失时仅用 short_range。与皮肤完全同色的衣物(如肤色裙摆/棕色膝贴)
             会有少量残留, 属像素级判据固有限制。
             首次启用会自检两通道差异并在日志报告；未检出皮肤时自动退回单通道。
             代价: 每帧两遍渲染，实时帧率约减半(导出同样变慢)。
  叠加显示遮罩 [默认关]: 在 DLSS 输出上叠加绿色皮肤遮罩，调试用。
  肤色判据分组: 9 个滑条(Cr/Cb 中心与容差、色相中心/容差、饱和上/下界、亮度下界)
             调肤色判据，默认值兼顾真实皮肤与 CG 浅肤；拖动实时重算遮罩(时域平滑自动重置)，
             配合“叠加显示遮罩”观察；分组内“皮肤遮罩覆盖率: XX%”标签实时反馈。
             参数随 settings 传递，切换素材不丢失；滑条范围外自动钳制；
             “恢复默认”一键还原；OpenCV 后端下极端值使遮罩失效时警告并自动恢复默认。
             “一键自动调优”: 基于当前帧种子(模型皮肤类/人脸椭圆∩宽松判据)颜色统计
             推导中心值与容差，再迭代缩放容差使覆盖率逼近 40%~60%(分割只跑一次约 0.1s)；
             结果经滑条边界钳制；完成后日志输出 Cr/Cb 中心与覆盖率。
  输出(与"DLSS 设置"并列的一层): 输出视图(处理/差异×10/左右对比) + 导出按钮 + 导出质量。
             导出时一律以当前 DLSS 设置的数值为准(输出混合已取消)。
  实时截屏测试: 选显示器 → 点"⬚ 框选区域"(或直接点"开始"自动进入框选)，屏幕变暗
             后按住左键拖出一个矩形，松开即选定(区域太小/ESC/右键=取消)。再点
             "▶ 开始截屏测试"，只实时抓取这块区域→降到 ≤720p→DLSS 渲染，结果显示
             在上方预览区(同样支持 原图/DLSS/对比 视图与分界线拖动)，旁边显示实时
             渲染帧率；改 风格/强度 等参数同样实时生效。点"停止"即恢复原来的媒体
             预览，已选区域会保留，可直接再次开始或重新框选；换显示器后开始时会
             自动检查区域是否仍在该屏内。截屏进行时导入/播放/导出按钮自动置灰。
             后端: 优先 DXGI(dxcam，GPU 侧、快)；混合显卡等不支持时自动回退 GDI
             (纯系统 API，稳定、无需额外安装)。受保护内容(如视频网站的加密播放)
             可能截到黑屏，属系统限制。
  导出 DLSS 视频: 按当前设置对整段视频批量生成后写入 mp4(处理/差异/左右对比)。
             导出在后台以"解码∥遮罩多路并行∥GPU 渲染∥写盘"四级流水线执行，界面不卡顿、
             进度条实时更新；导出中重复点击会被拒绝。完成后弹窗提示输出路径。
             导出质量(CRF 0-51，越小越清晰、文件越大，默认18)：用 ffmpeg(libx264) 编码；
             本机装有 ffmpeg 时生效，否则自动回退 OpenCV 内置 mp4v(此时画质项不生效，日志会提示)。
  在导出栏输入 CRF 值 → 点"导出 DLSS 视频"即可。

【文件夹内容】
  gui.py            界面 + 播放/导出逻辑(导出已线程化四级流水线 + 遮罩多实例交错帧)
  audio_out.py      播放音频(ffmpeg 流式解码 + sounddevice 输出)
  screen_cap.py     屏幕截取(DXGI/dxcam 优先，GDI 兜底)
  dlss_engine.py    ctypes 调 dlssnr_host.dll(含 CpuLive 纯 CPU 回退渲染)
  skin_mask.py      皮肤遮罩提取(MediaPipe 分割+双人脸检测+高分辨率肤色/纹理融合, OpenCV 兜底)
  perf_profile.py   GPU 硬件分级检测与自适应性能配置(低/中/高/旗舰/无GPU 五档+运行时升降档+遮罩并行路数)
  fetch_models.py   (可选)重新下载 models/ 下的 MediaPipe 模型
  models/           (可选)selfie_multiclass_256x256 + blaze_face_short_range
                    + blaze_face_full_range(可选, 全身照小脸检出)
  dlssnr_host.dll   自编译 D3D12 + NGX Feature 18 宿主(含签名门禁绕法)
  nvngx_dlssnr.dll  NVIDIA DLSS5 神经渲染运行时(默认自带 40 系版本)
  ..\30系\ ..\40系\ ..\50系\   (可选)按 GPU 系列适配的 nvngx_dlssnr.dll 附加包:
                    源码运行: 解压到本工具文件夹的【旁边】;
                    EXE 版: 解压到 DLSS5Tool.exe 所在目录(与 _internal 同级)。
                    启动时工具按显卡型号自动选用(型号不在 30~50 系或文件夹
                    不存在则回退自带默认库, 日志可见选的是哪份)。
  run.bat           启动脚本
  README.txt        本说明

【自行打包 EXE】
  python -m pip install pyinstaller，然后在工具目录下运行:
    python -m PyInstaller --noconfirm --windowed --onedir --name DLSS5Tool
      --add-binary "dlssnr_host.dll;." --add-binary "nvngx_dlssnr.dll;."
      --add-data "models;models" --add-data "README.txt;."
      --collect-all mediapipe --exclude-module matplotlib gui.py
  产物: dist\DLSS5Tool\DLSS5Tool.exe(约 440MB, 自带 40 系默认库)。
  注意: mediapipe 是函数内延迟 import, 必须加 --collect-all mediapipe, 否则打不进去。
  自检: 运行 "DLSS5Tool.exe --selftest", 成功会在 exe 旁生成 _selftest.txt,
    写入 DLSS_OK 与 SKIN_OK 两行(后者验证皮肤遮罩 mediapipe 后端在冻结包里可用)。
  历史坑(修复已内置在 gui.py 顶部冻结兼容层, 重打包无需处理, 仅供排障参考):
    1) --exclude-module matplotlib 后, mediapipe 的 drawing_utils 模块级
       `import matplotlib.pyplot` 会断(症状: 皮肤遮罩回退 OpenCV、覆盖率极低、
       一键调优返回默认值“点击无反应”)。gui.py 预置了空壳模块。
    2) sounddevice 在无系统 PortAudio 时 `import _sounddevice_data` 取 __path__,
       而 PyInstaller 把它收成无 __path__ 的空模块, 连带 mediapipe import 失败。
       gui.py 预置了带 __path__ 的模块指向 _internal 数据目录。

【对方电脑要求】
  ◆ EXE 版(把 dist\DLSS5Tool 整个文件夹拷给对方)——什么都不用装:
  1. Windows 10/11，NVIDIA 显卡(建议 RTX 30/40/50 系)，装最新驱动。
     笔记本混合显卡(核显+独显)时，需在 设置→屏幕→图形 里把 DLSS5Tool.exe 设为
     "高性能"，否则 DLSS 初始化会失败(0xBAD00001)。
  2. 不需要装 Python、不需要 VC++ 运行库: 解释器(python312.dll)与全部依赖
     (numpy/OpenCV/mediapipe/Pillow/sounddevice 含 PortAudio、tk 界面库、模型)
     已打进 _internal，VCRUNTIME140.dll 也随包(实测核对过)。整个文件夹一起拷，
     别拆散别单独拽 exe 出来。
  3. (可选) ffmpeg——不装也能用: 导出由 OpenCV 内置编码器写(画质项不生效)，
     播放静音(日志会提示)。装了则"导出质量(CRF)"真正控制 mp4 画质、播放有声:
     ffmpeg.org 下 release-essentials 包解压，把里面的 bin 目录加入 PATH。
  4. 渲染库与 GPU 系列强相关: 实测 50 系库在 40 系卡上 CreateFeature 直接失败
     (0xBAD00001)——显卡是 30/50 系时务必使用对应系列的附加包
     (解压到 exe 同级，与 _internal 同层)，用错系列不是效果差而是完全起不来。
     30 系与 40 系库在 40 系卡上输出逐位一致。

  ◆ 源码版(python gui.py)——对方电脑需要:
  1. Windows/显卡/驱动要求同上(混合显卡时把 python.exe 设为"高性能")。
  2. Python 3(勾选 Add to PATH)，然后:  python -m pip install numpy opencv-python pillow sounddevice
     (用 "python -m pip" 而不是裸 "pip"，避开多个 Python 共存时装错解释器)
     (tkinter 随 Python 自带；sounddevice 的 Windows 安装包自带 PortAudio)
     Pillow 是预览必需：缺它时工具能启动但预览区空白，日志提示
     "[preview] 预览需要 Pillow：python -m pip install pillow"(导出不受影响)。
     若日志报的是 "DLL load failed ... _imaging" 则是 Pillow 装了但缺 VC++ 运行库，见第 3 条。
     皮肤双通道还需要:  python -m pip install mediapipe  (装不上也能用，自动回退 OpenCV 肤色判据)
  3. VC++ 2015-2022 运行库(vcruntime140.dll)——缺则装 "Microsoft Visual C++ Redistributable"。
  4. 所有文件放同一文件夹(别移动 DLL)。显卡是 30/50 系时，系列附加包解压到
     本工具文件夹的【旁边】(见开头文件夹内容说明)；ffmpeg 可选，同 EXE 版第 3 条。

【重要限制】(已实测)
  - Feature 18 神经渲染在本配置下忽略光流/深度引导(零引导)，所以不需要深度/光流模型和 torch；
    也因此【预设/引导模式】等项对画面无影响，故本简约版只保留真正有效的参数。
  - 【换视频/图片】已支持：重新导入同一尺寸会复用 DLSS 会话；导入不同尺寸会重建 feature
    (不重初始化 NGX，避免崩溃)。NGX 核心初始化本身仍是一次性的，但可由宿主 resize 安全换档。
  - 导出在后台线程四级流水线执行(解码∥遮罩多路并行∥GPU 渲染∥写盘)，界面不卡顿；
    导出进行中再次点击导出会被拒绝，属正常。
  - 播放实时性取决于 GPU：<720p 源一般能满帧率；更高分辨率在速度=1.0 时自动降到
    ≤720p 处理，若仍跟不上则"保持最新帧"(日志提示)，播放头与声音不受影响；
    想全分辨率看效果就选更低速度(如 0.5/0.25)，以慢放换满清渲染。

【性能优化与自适应】(P0-P6)
  GPU 分级检测: 启动时经 nvidia-smi 读取型号/显存，自动分档并写入日志——
    旗舰(RTX 4080/4090/5080/5090 类, ≥15GB)、高配(RTX 5070/5070Ti/4070/3080 类, ≥10GB)、
    中配(RTX 或 ≥6GB 显存)、低配、无GPU(CPU回退)。50 系为主流, 5070~5090 至少落在高配。
    同时按型号系列(RTX 30xx/40xx/50xx)自动选用 上一级\<系列>\ 里的 nvngx_dlssnr.dll
    (没有就回退自带默认库; 选库只在 NGX 首次初始化前发生, 之后锁死不再切换)。
  参数自适应: 各档对应不同的遮罩参数(720p 实测定档)——
    整遮罩复用步长(质量主杠杆: 旗舰/高配每帧全量重算, 中配隔帧、低配隔两帧复用)、
    分割时域复用步长(旗舰每帧、高配隔帧、中低配每 3 帧)、纹理门控核尺寸(低配3×3/其余5×5)、
    时域 EMA 平滑系数(复用步长越大权重越高, 补偿滞后)。
    融合分辨率全档固定 768: 隔离实验显示 768 与 1024 的输出遮罩 IoU 0.987(几乎同一张图),
    而 1024 每帧多花 18~65ms——加大它买不到质量, 故不作为档位阶梯。
  遮罩多路并行(P6, 突破 CPU 遮罩墙): 导出时按档位开 2~3 个独立遮罩实例跑交错帧
    (实例0 处理帧 0/3/6…、实例1 处理帧 1/4/7…)，各自持有独立的分割/原始遮罩缓存，
    把原本串在一条 CPU 线上的遮罩计算摊到多核。路数上限: 旗舰/高配 3、中配 2、低配 1，
    再受 CPU 逻辑核数(不超 核数/4, 给编码留核)与帧面积(≥6M 像素即 4K 级压到 2 路)约束。
    时域 EMA 不能留在实例里: 每实例一条 EMA 链会让相邻帧来自不同链, 实测(运动补偿后)
    闪烁升到串行的 1.41~1.67 倍。改成: 实例只算不含时域状态的单帧遮罩, EMA 挪到严格
    按帧序的汇合点用单一状态递推 —— 输出与单实例串行【逐位一致】(实测最大差 0, 闪烁 1.00x)。
    多路时强制关掉遮罩/分割的隔帧复用(否则缓存陈旧度会被路数乘掉, 静默降质);
    运行时调档改成只记 epoch、由各实例在确定空闲时自行补应用(不与正在跑的遮罩竞争)。
    代价: 每多一路约 +130MB 常驻内存。额外实例在导出结束后只清时域状态、留着复用而不
    销毁 —— 实测 MediaPipe 任务对象的 close() 要干等约 100s 才返回(几乎不吃 CPU, 但同进程
    遮罩耗时会涨到 2.2 倍): 同步关会让"导出完成"硬生生晚 100s, 扔后台线程则拖慢下一次导出。
    预览仍是单实例、EMA 在实例内(逐帧交互无法预取), 导出结束会把档位参数重新应用回去。
  运行时动态调档: 导出过程中每 2s 采样 GPU 利用率——利用率持续<30% 且帧率不达标
    自动降一档(加大复用步长)；GPU 满载且帧率充足再升回(不超过启动档位)。
  CPU 回退: 无 NVIDIA GPU / D3D12 初始化失败时自动切换纯 CPU 渲染管线(OpenCV 锐化+
    色彩增强替代神经渲染)，状态栏显示"CPU 回退模式"，日志一次性提示性能上限有限。
  实测(本机 RTX 4080 + i7-13700K, 720p+皮肤双通道, 走真实导出管线):
    锁死旗舰档做同画质对比 —— 遮罩 1 路 147.5ms/帧(6.78fps) -> 2 路 86.5ms/帧(11.56fps,
    1.71x) -> 3 路 60.9ms/帧(16.43fps, 2.42x); 对比 P5 的旗舰档 175.8ms/帧共快 2.89 倍。
    阶段重叠实测: 3 路遮罩总和忙 3.82s, 而它们占住的墙钟(区间并集)只 1.56s(并行度 2.45x);
    GPU 忙时的 86% 与遮罩重叠(真并行)。
    P5 分项仍生效: 双通道混合 48.98→7.80ms(仅在遮罩包围盒内混, 最大误差 1/255)、
    输入组装 3.07→0.06ms(cvtColor 直写复用缓冲)、写盘 tobytes 全帧拷贝→memoryview 零拷贝。
  瓶颈说明(重要): 皮肤遮罩跑在 CPU(MediaPipe), 720p 单实例每帧全量约 105~160ms, 而 GPU
    双通道只要 33ms/帧——开启皮肤双通道时瓶颈在 CPU 而非显卡。P6 把这道墙推高了约 2.4 倍
    (旗舰档 6.8→16.4fps), 但性质未变: 换更强的显卡仍不会明显更快, 换核更多的 CPU 才会;
    想再快就关闭"皮肤双通道"或用中/低档(隔帧复用遮罩)。

【原理】
  用 NVIDIA DLSS5 神经渲染(Feature 18, 同分辨率增强/去噪)对视频/图片逐帧处理。
  宿主 DLL 预编译并内置 SDK 签名门禁绕法(caller 伪装 + Init_Ext 0x0876232C)。
  播放采用后台工作线程顺序解码+处理(单槽最新帧缓存)，UI 以 16ms 节拍按音频/墙钟显示。

【可选调优】
  单帧速度: 640x360≈60ms, 1080p≈150ms, 4K≈300-500ms。
  逐帧细看用帧进度条；整段效果用"导出 DLSS 视频"。
